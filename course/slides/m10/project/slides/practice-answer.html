Internomics · Module 10 — Diagnose the Coordination Problem

Here's how I'd read it. One: this is mostly coordination failure. Run the test: if I knew everyone else would use the calendar, would I? The team's own words, "that's where everyone else's dates are," say yes. They aren't opposed to the tool. They're unwilling to switch alone, because a calendar one person uses is worse than spreadsheets everyone checks. Two: the barrier is strategic uncertainty. "When you can" gave no shared date, no plan and no visible sign anyone else was switching, so everyone waited. From the outside, that looks like resistance to change. Three: the newsletter broke at the handoff. Nobody opposed the review; there was no clear owner. Four: motivation isn't the bottleneck. Announce it in a team meeting, so everyone sees everyone hear it: starting Monday the 3rd, the shared calendar is the only calendar, spreadsheets are retired. Name an owner for keeping it current, define what "scheduled" means, and review it briefly each week so people see others using it. The calendar becomes the focal point, which also stops colliding sends. And for the newsletter: the writer submits for compliance review; nothing goes out without sign-off. Five: possibly not all coordination. If, once expectations are public, some people still skip it because updating is extra work that mostly helps others, that's a social dilemma. Diagnose first, and re-diagnose if the fix doesn't hold.
