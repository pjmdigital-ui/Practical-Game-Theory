Example · Choosing a system

The better tool, or the one everyone uses?

The situation: A team is choosing a project-management system. System A is slightly better. System B is already used by everyone in the company.

The temptation: Spend weeks proving that A has better features.

What happens: Half the organization stays on B. You've created a coordination failure.

The lesson: A slightly inferior standard used by everyone can beat a superior standard used by half the group.

Internomics · Module 10 — Diagnose the Coordination Problem

This example can be hard for highly analytical people. I include myself in that. Imagine a team choosing a project-management system. System A is slightly better. System B is already used by everyone in the company. Which should they choose? The analytical instinct says A. And you could spend weeks proving that A has better features. You could build a comparison chart. You could win the argument. But think about what happens next. If half the organization stays on B, you haven't improved anything. You've created a coordination failure. Now there are two systems. Work falls between them. People have to check both. Every handoff gets harder. So sometimes a slightly inferior standard used by everyone is more valuable than a superior standard used by half the group. Let me be careful here, because this gets misheard. It doesn't mean quality never matters. It does. If B were truly broken that would change things. It means coordination itself has value. And that value has to go on the scale next to the features. When you compare options in a coordination game, ask two questions instead of one. Which option is better on its own? And which option can everyone reliably land on? Here's a question for you. Is there a tool or a process at your work that you keep fighting because something better exists? What would it cost if only half the people followed you to the better one? Let's put this lesson on one line.
